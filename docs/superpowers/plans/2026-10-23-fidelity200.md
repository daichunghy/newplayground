# NewPlayground Fidelity and 200 Games Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development. Worker/reviewer: gpt-6-luna, high, as requested by the user. Do not spawn additional workers.

**Goal:** Improve the existing 150 entries, add 50 independently playable games, simplify the UI and preserve honest per-game fidelity status.

**Architecture:** Exact-ID registry preceding legacy routing; shared session/input/presentation helpers, distinct game models. Static script packs load before app.js; final integration synchronizes both catalogues and verifies 200 entries.

**Tech Stack:** Vanilla JavaScript, HTML/CSS, Canvas2D, Node built-in test runner.

**Spec:** docs/superpowers/specs/2026-10-23-fidelity200-design.md

## Global Constraints

- Static app, no product CDN/runtime dependencies; Calibri first; touch targets >=44px.
- All worker/reviewer agents: gpt-6-luna with reasoning_effort high; no worker may spawn agents.
- Own only task files; do not change unrelated engines or commit other workers' work.
- Register exact IDs; new games cannot delegate gameplay to NP_Archetypes or relabel an unrelated game.
- Use NP_GameSession for listeners/timers/RAF/cleanup/pause; no orphan callbacks after replay/close.
- UI: one short contextual hint, no long mandatory rules or decorative subheadings; accessible real buttons.
- Document references actually inspected and limitations honestly; do not claim absolute fidelity from smoke tests.

## Review Focus

- Illegal moves, terminal state and restart must be tested on actual model behavior.
- Touch cancellation, held input, pause/resume and close must not leave actions running.
- Generated puzzles must be solvable; preset puzzles must have verified solutions.
- AI may only make legal moves, including forced captures/draw/pass rules where applicable.
- Catalogue fallback and script order must work with blocked network/storage and all 200 IDs.
